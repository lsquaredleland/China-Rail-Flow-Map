## 1. Executive summary

This is a strong project for its size: a Rust pipeline with real statistical routing (a per-train HMM over candidate corridors with learned run-time likelihoods, 94% leave-one-out accuracy on self-checks), a compact five-file `fmt: 5` pack with hard pack-time assertions, a machine-checked goldens gate, and a client that decodes once at load and runs a single `trainDistAt` position model. The staging-first discipline in the docs is real, and the progress log is unusually honest about what is and isn't verified.

The weaknesses are structural rather than sloppy: the router and the section builder are **non-deterministic by construction** (HashMap iteration feeding non-transitive comparisons), the atlas and audit binaries are two 3,000-line `main()`s that share ~900 identical lines with **zero tests**, the live recipe depends on a hand-splice (`o9_splice_router.py`) that exists only because of the non-determinism, and the deploy config caches un-hashed assets as immutable for a year. I also found one **design/implementation divergence that changes flows**: the "canonical" pair geometry is the *shortest* gap-free candidate, not production's own path, for ~13% of pairs.

**Top 5 recommendations, ranked**

1. **Make the router deterministic (O17)** by removing the three real sources: HashMap iteration in `min_gap_bridge` (`router/src/main.rs:277-299`) combined with its non-transitive 50 m tolerance (`:320-325`), stitch-edge adjacency order from `best.values()` (`router/src/graph.rs:356`), and the general "iterate a `HashMap`, compare floats with a tolerance" pattern. Fix = sort keys + lexicographic `(gap_bucket, total, node_a, node_b)` tie-break. Until this lands, every router rerun needs a splice, which is unreviewable process debt. *Staged rebuild + gate run required.*
2. **Decide what "canonical pair geometry" means and make the code match the comment.** `best_for_canon` (`router/src/main.rs:901-907`) picks the shortest gap-free candidate; the comment (`:895-899`), the file's `about` text (`:1024`) and `docs/corridor-v3-report.md` all say "redrawn within 200 m of itself". On the shipped `candidates.json`, 862 of 6,596 gap-free production pairs get a *different* corridor as their default (368 by >2 km; e.g. 上海虹桥–江阴 163.4 km on 沪宁沿江高速/沪苏通 → 157.4 km on 京沪/新长). This silently bypasses the per-train inference for every "production"/"ambiguous-keep" leg on those pairs. *Flows change; staged rebuild + owner approval.*
3. **Make `atlas` section building deterministic (O18)** by seeding chains from a sorted edge list instead of `edge_sig.iter()` (`atlas.rs:2638`, `:2826`) and fixing a canonical chain direction. With fmt 5's long-paths-first renumbering this makes packs byte-reproducible, turns `secdiff` into `diff`, and lets CI compare PR packs to main at the byte level. *No flow change; goldens unchanged.*
4. **Fix the deploy cache contract**: `vercel.json` sends `Cache-Control: public, max-age=31536000, immutable` for `/assets/*`, but the client fetches fixed names (`App.tsx:63-68, 86`). After any asset swap, returning users get a fresh `index.html` and year-old data — at a format bump that is the `FmtError` overlay for everyone with a warm cache. Content-hash the pack filenames via a tiny manifest, or drop `immutable`. Also serve `.br` with `Content-Encoding: br` so the 91 KB JS decoder path (`App.tsx:98-147`) is bypassed. *Client-only, no rebuild.*
5. **Put the atlas/audit shared code and the hard-coded gazetteer behind tests.** `atlas.rs` and `audit.rs` share 23 function names and 917 identical lines (including a 540-literal `CORE`/`ALIAS` city table at `atlas.rs:7-558`, duplicated verbatim in `audit.rs`), and the whole `analyze` crate has no `#[test]`. Extract `analyze/src/atlas_common.rs`, add unit tests for `orient_leg`, `walk_edges`, `leg_key3`, section chaining and the pack round-trip, and run `audit --pack-only` on the committed pack in CI (O12/O13). *No data change.*

## 2. What's good

- **The routing model is the right shape for the data.** Observations exist only at stops, so a per-leg candidate set with an HMM across legs (`model.rs:527-568`, reversal transition `:510-523`) is the correct abstraction; a per-edge Newson–Krumm map-matcher would add states without adding evidence. The run-time model with a braking curve (`model.rs:79-81, 172-241`), per-class calibration via binned KDE (`model.rs:371-431`), asymmetric slow-side tail (`model.rs:441-452`) and the demonstrated-corridor prior (`main.rs:1125-1190`) are all principled, and the leave-one-out self-check (`main.rs:1197-1368`) measures exactly the thing that matters.
- **Conservative switching.** Leaving production requires posterior ≥ 0.9 *and* production ≤ 0.05 (`main.rs:829-834`), and an override can never make a leg less resolved than base (`atlas.rs:1399-1467`). The decision ledger per leg (`leg_routes.jsonl`, `main.rs:975-982`) makes every switch auditable.
- **Double track is treated as one corridor where it counts.** Candidate distinctness, production-merge and the diversification penalty are all geometric at 150 m (`model.rs:273-343`, `main.rs:168, 207-215, 248-252`), the redraw constrains to a 200 m buffer with same-line 30 m hops (`graph.rs:636-717`, `main.rs:365-416`), and `F_PROD` biases searches onto already-drawn track (`graph.rs:17-19, 396-403`).
- **fmt 5 pack is tight and self-checking.** Per-train path dedupe with per-row suffix/prefix offsets, delta-coded flows and long-paths-first renumbering (`atlaspack.rs:481-535`), every row hard-asserted to be a slice of its train's path (`atlaspack.rs:621-637`), every file carrying `fmt` and the client refusing anything else (`lib.ts:1064-1074`). First paint ≈ 1.1 MB brotli (shared 529 KB + out-map 546 KB + outline 33 KB), total 5.3 MB.
- **Goldens gate with exact/max semantics** (`pipeline/goldens.json`, `audit.rs:1664-1735`): fails on any exact change or max rise, prints "improved" when a max falls, requires a deliberate `--update-goldens`. Dropped chains / flow lost are exact zeros.
- **Orientation is asserted, not assumed.** `atlas.rs:2938-3031` orients every leg from coordinates and panics if a stored pair path isn't key-ordered — the kind of invariant that protects the whole signed-path encoding.
- **One position model in the client.** `trainState`/`trainDistAt` (`lib.ts:967-1022`) drives dots, flow lighting (`timeAtDist`, `lib.ts:1026-1056`) and city-pair lighting (`MapCanvas.tsx:689-729`); no per-frame geometry work, scratch object instead of allocation.
- **Rendering is batched sensibly.** Flows are grouped into one stroke per (0.25 px width, colour) bucket with bbox culling (`MapCanvas.tsx:776-814`), `traceInto` skips sub-pixel points (`:363-391`), DPR capped at 3 (`:2043`).
- **Engineering hygiene**: `strict: true` TS, `clippy -D warnings` + `fmt --check` + `cargo test` in CI (`.github/workflows/ci.yml`), rayon parallelism with per-thread stamped buffers (`graph.rs:439-455`), `serde_json` `preserve_order` so emitted JSON key order is deterministic.
- **Documentation quality.** `optimization.md` bug ledger B1–B21 with root causes and fix locations, and a progress log that records negative results (e.g. the `[]`-overrides vs live discrepancy, the 490-leg router drift).

## 4. Routing algorithm assessment

### 4.1 How it works today (end to end)

1. **Base pair geometry** (`analyze/src/bin/paths.rs`, not re-reviewed in depth): shortest path per unordered station pair on the `railway=rail|ferry` graph with 250 m component stitching; pairs with no track get `bridged` (≤10 km straight-line hop) or `via_chain` status. Output `pair_paths.json` + `pair_distances.json`.
2. **Router graph** (`router/src/graph.rs:179-382`): same topology, plus `vmax` (tagged `maxspeed`, else role default), `F_HSR`, `F_SERVICE`, line name, and `F_PROD` for edges on production paths (3% cost discount, `:19, :396-403`).
3. **Candidates per pair** (`main.rs:143-267`): A* (`graph.rs:558-629`, multi-source/target over snap sets within 1.5 km) for the fastest path per class group present, the shortest, up to 3 penalty-diversified alternatives (×4 cost on every edge within 150 m of an existing corridor), then production's own geometry — merged into an existing candidate when both cover ≥ 90% of each other, else appended. Acceptance: ≤ 2×chord+40 km, ≤ 1.6×shortest+30 km, < 80% covered by any existing shape.
4. **Calibration** (`main.rs:650-686`, `model.rs:371-431`): for legs whose gap-free candidates predict within 4% of each other, x = ln(scheduled/predicted) per class → binned Gaussian KDE (bw 0.04) with a hard floor at the 0.5th percentile − 0.05.
5. **Bridging** (`main.rs:688-736`, `:273-350`): for production-bridged pairs, candidate-less pairs, or pairs where some leg is infeasible on every candidate, search dangling track ends (degree 1) within a radius for the smallest plausible gap (≤10 km, 0.95–1.45× chord, ≤355 km/h).
6. **Service prior** (`main.rs:1125-1190`): for every stopping train span A…C with ≤6 intermediates, which candidates pass within 1 km of all the intermediates → Laplace-smoothed per routing group, weight 2.
7. **Inference** (`main.rs:749-894`, `model.rs:459-568`): emissions = calibrated log-likelihood − 3·ln(km/kmin) + service prior; chains of consecutive legs with candidates; transition −4 when the dwell is < 6 min and headings flip by > 150°; forward-backward → marginals → per-leg argmax → decision (`switched` / `bridge-fix` / `filled` / `chord` / keep).
8. **Canonical geometry + redraw** (`main.rs:895-948`): `best_for_canon` picks a candidate per pair (see R1), 4 rounds of usage-weighted redraw within 200 m with same-line hops; chosen non-production corridors redrawn the same way. Outputs `pair_paths_canonical.json` (consumed as the pair geometry) and `leg_paths.json` (`#cv3:pi:k` ids keyed by `train_no`).
9. **Atlas resolution** (`atlas.rs:1187-1487`): a leg key is `(min, max, via)`; `via` is a router id, a legclass waypoint chain, or empty; resolution order router path → pair path → corridor-chain Dijkstra over station-level `pair_len` (`dijkstra_chain`, `:907`) with ≤1.6×chord+20 km; variants fall back to base.
10. **Sections** (`atlas.rs:2552-2757`): trim edges whose midpoint is within 1.3 km of a station (B8); per edge, per origin city, count *distinct* trains; intern the per-city count vector as a signature; chain edges of equal signature through degree-2 nodes; Douglas–Peucker at 3.5e-4°, round to 1e-4; HSR flag per chain.
11. **Per-train paths** (`atlas.rs:3049-3079`): orient each leg from coordinates (`orient_leg`, `:1580`), walk directed edges into `edge_dir_to_sec`, emit signed section ids in travel order collapsing only back-to-back repeats; chord legs where a walk has a hole > 3 km; `dep_stop_pos` per station.
12. **Pack** (`atlaspack.rs`): renumber long-paths-first, dedupe paths per train, delta-code flows, hard-assert slices.

### 4.2 Weaknesses

- **Determinism** (R2, R3): detailed above. The fix is mechanical but must be done everywhere a `HashMap`/`HashSet` is *iterated* (not looked up) and everywhere floats are compared with a tolerance. A one-line defence is to type the few iterated maps as `BTreeMap` or iterate `let mut ks: Vec<_> = m.keys().collect(); ks.sort();`. For the bridge search, replace the tolerance predicate with a total order: `(round(gap / 0.05), total, a, b)`.
- **Canonical geometry** (R1): the single biggest unreviewed flow effect. Either (a) restore the documented intent — canonical = production's own path when `gap_km == 0`, shortest gap-free only when production is bridged — and accept that some pairs keep a longer-than-shortest default, or (b) keep "shortest" but then say so and validate it (the self-check only scores per-leg decisions). My recommendation is (a): the entire per-train inference is premised on "production unless decisive evidence", and (a) is the only choice consistent with that.
- **Section identity is a function of flows, not topology.** Because sections are maximal chains of equal per-origin count vectors over *all 102 origins*, any timetable change anywhere re-cuts sections nationally. That is why ids are unstable by design, why `secdiff` must compare edges, and why R4 exists. It also means "section" is not a thing a human can name.
- **Throat trimming is applied to both flows and paths.** The 1.3 km trim (`atlas.rs:2552-2566`) is right for widths (adjacent legs overlap at stations and would inflate short sections) but wrong for per-train continuity; that is the whole of O1 and B8. The O1 branch's geometry-only stubs are the right fix; its diff is 638 lines across `atlas.rs`/`audit.rs`/`lib.ts`.
- **Inference details**: marginal argmax (R10); the reversal transition uses end bearings over the first/last ~1.5 km (`model.rs:253-268`), which at a terminal loop or wye can mis-read a non-reversal as one (**uncertain** how often); `SVC_MAX_INTERMEDIATE = 6` and 1 km stop tolerance are untested knobs; `CONV_HSR_KM = 5` bars conventional classes from any candidate with >5 km of `highspeed`/≥250 track, which is correct for Z/T/K but the D-class (CAP 250, not barred) can be pushed onto 350 lines by the length prior.
- **Validation covers stopping trains only** (`corridor-v3-report.md` caveat). True nonstop legs — the ones the project exists to draw correctly (Chengdu–Chongqing) — have the weakest evidence and no held-out test. The approved spot-check protocol (single-train 12306 pulls) is the only ground truth and should be turned into a small committed fixture of adjudicated legs that the audit scores.
- **Station snapping** picks up to 48 nodes within 1.5 km or the single nearest within 6 km (`graph.rs:478-514`); multi-station cities and homonyms (`禹州`, `郏县`, `阳江`) already needed `station_fixes.json` and `pair_path_fixes.json`. Snapping by *name* across datasets is the standing source of the O9 class of bug.

### 4.3 How I would do it better

**A. Deterministic tie-breaking (do first, smallest, enables everything else).** Replace iterated `HashMap`s with sorted iteration; replace tolerance comparisons with lexicographic total orders; stitch edges sorted by `(comp_a, comp_b)`. Add a CI-able determinism test: run the router twice on a small `--pair` subset and `cmp` the outputs. Cost S–M, risk low, impact: full reruns become reviewable, the splice goes away. *Staged + gate.*

**B. Two-level model: a corridor catalogue, then train assignment.** Build once, deterministically, a *station-level multigraph* whose edges are named corridors between adjacent stations (from OSM `name`, merged across parallel ways of the same line within ~30 m, split at junctions and stations). Route trains on *that* graph (candidates = simple paths in the multigraph bounded by length ratio), keep the same HMM/emissions. Sections become catalogue edges (stable ids, human-readable: "沪宁沿江高速线 江阴–张家港"), double-track merging is a one-time preprocessing step rather than a 4-round usage-weighted redraw, and the 8-class breakdown is exact per catalogue edge. Trade-offs: loses per-track fidelity inside stations (acceptable at map scale; O1 stubs still needed for dots), needs care at flyovers and where OSM `name` is missing (`NO_LINE` ways — fall back to geometric clustering), and is an M–L rewrite of `atlas.rs` section building and `atlaspack` ids. The payoff is that ids stop churning, `secdiff` becomes trivial, and R4 disappears by construction.

**C. Topology-cut sections as a cheaper step toward B.** Keep the current edge-level flow counting but cut chains at every node of degree ≠ 2 in the *union flow graph* (not in the per-signature graph). Train sets are then constant within a section by construction (a train can only join/leave at a junction or a trimmed station), R4 goes away, and ids become stable under timetable changes that do not add track. Expect more sections (**uncertain**, perhaps 1.5–2×) and slightly larger `flows` arrays; measure in staging. Cost M, no flow change.

**D. Viterbi + margin reporting.** Decode the MAP chain and record `post[best] - post[second]` in `leg_routes.jsonl`; gate the goldens on the count of decisions within ε of a threshold so R2-style drift is visible even after A. Cost S.

**E. Map-matching / HMM over the rail graph.** Not recommended as a replacement: without positional observations between stops, a per-edge HMM has nothing to match. The current per-leg candidate HMM *is* the appropriate HMM. Where a finer model helps is *within* a candidate (which of two parallel tracks) and that is better solved by B's merge than by more states.

**F. Precomputed station-to-station paths / contraction hierarchies.** The router already takes ~20 s nationally; CH would speed candidate generation but the cost is in diversification and redraw, not in single A*. The useful precomputation is B's catalogue plus a per-pair candidate cache keyed by a hash of (graph, station points, parameters), so a rerun only recomputes pairs whose inputs changed — that is what would have made O9 a 5-second incremental run instead of a splice. Cost M.

**G. Station identity.** Resolve stations to OSM `railway=station` node ids once (a committed `station_resolution.json` already exists) and key everything by id, not name; the name is display only. Removes the homonym class of fixes at the root. Cost M; changes flows for the affected pairs. *Staged + approval.*

## 5. Data pipeline and asset format

**Reproducibility.** The build is reproducible in *flow identity* but not bytes, by design (R2/R3), and only on this machine (R6). The chain is: handoff inputs (not in git) → router (non-deterministic) → splice (`o9_splice_router.py`) → `atlas` (non-deterministic ids) → `atlaspack` (renumbers) → `audit` (gate) → `secdiff --edges` vs a live v1 snapshot in `staging/`. Fix A + O18 makes the last four steps byte-stable; the migration plan in `optimization-progress.md:296-300` addresses R6 and should include committing `data/raw/*.jsonl` (they compress ~7× to ~6 MB per `PIPELINE.md` §2) or at minimum a checksummed manifest. Remove `data/` from `.gitignore` in favour of explicit `data/osm/`, `data/derived/`, `data/raw/` entries so new fixtures are not silently dropped.

**Gates.** `goldens.json` is good; add: `sum(class counts) == total` per flow row (R4), decision-margin counts (D), a determinism check (A), and an `about`/recipe hash in `shared` so a pack records which overrides/paths it was built with (the `[]`-vs-overrides confusion in R16 would have been impossible). `--pack-only` skips `dropped_chains`/`flow_lost` (O8) — those two are cheap to recompute from the pack itself (every row's legs vs its sections), which would let CI enforce them.

**Pack format.** fmt 5 is well designed: typed array rows, integer minutes, geometry as polyline strings at 1e-4, brotli. Sizes: shared 529 KB, out-map 546 KB, in-map 550 KB, out-tables 1.56 MB, in-tables 1.72 MB, schedules 418 KB, outline 33 KB. The tables dominate (per-train signed paths, 7,157 trains). Options, in order of value per effort: (1) nothing until A/O18 — reproducible bytes matter more than 10%; (2) varint-pack `paths` into a base64/`Uint8Array` field — **uncertain** gain after brotli, measure before committing; (3) the already-planned lazy in-tables load. Do *not* drop geometry precision: 1e-4 (~10 m) is already at the merge tolerance.

**Serving.** See R5: hashed filenames + `Content-Encoding: br` + `Content-Type: application/json`. The `fetchData` ladder already prefers server-negotiated encoding (`App.tsx:98-101`), so this is a config-only win (verify Vercel does not re-encode a pre-compressed body — **uncertain**).

## 6. Client

**Architecture.** React 19 shell (`App.tsx`, 1,594 lines, 10 effects) around one imperative canvas component (`MapCanvas.tsx`, 2,959 lines) that holds props in `P.current` and mutable draw state in `S.current`. The atlas is a shared mutable object: staged table loads `Object.assign` into `at.data.origins[i]` (`App.tsx:357-384`) and flip ready flags that re-run `useMemo`s. It works, and it is fast, but it is the kind of design where the invariants live in the authors' heads (the B14/B21 class of bugs came from exactly this). A small typed store (`AtlasStore` with `applyOutTables` etc. as the only writers) would make the phases explicit without a framework change.

**Rendering/perf.** Every frame redraws outline, graticule, the full network backdrop (bbox-culled but not cached), flows, infra, trains, stations and labels (`MapCanvas.tsx:1940-2000`). On a phone at 60 fps that is the dominant cost; `PIPELINE.md` §6.2 already names backdrop caching as the first perf item. Concretely: render outline+graticule+network to an offscreen canvas keyed by `(view, size, DPR, palette)` and `drawImage` it; render static flows to a second layer when not animating. Per-frame allocations (R15) are easy wins: one shared gradient per class (translate the context instead), a reused `Map` for active counts. The 5-min `secFlowSteps` tables (`lib.ts:1360-1392`) are `Map<sec, Uint16Array(numSteps)>` — ~7.5k × ~800 steps × 2 B ≈ 12 MB for a long-span origin; fine on desktop, worth checking on a phone (**uncertain**).

**State/URL.** `?city=&lat=&lon=&z=` sync with debounce (`App.tsx:321-349`, `MapCanvas.tsx:2017-2023`), persisted dark/direction/unit in `localStorage`. Good; guard `localStorage` with try/catch (R14).

**Tests.** None. `tsc --noEmit` and a build are the whole CI for `web/`. The one real test harness is `scripts/check_pack_roundtrip.mjs` (bundles the real `lib.ts` with esbuild and compares two packs by geometry) plus the gitignored `staging/scripts/check_client_decode.mjs` / `check_filter_animation.mjs`. O13 is the right call: promote these into `web/tests/` under `bun test` with the committed pack as fixture; the invariants are already written down (`trainDistAt` monotone, dwell == stop.dist, final-step flows == static flows, animated ⊆ filter, 0 jumps outside chord legs).

**Correctness nits.** `prepAtlas` city-coordinate patches (`lib.ts:454-467`, O10) belong in the gazetteer; `lib.ts:1269` silently produces no dwell stops when `nStops !== train.stops` or the schedule is short — log it once in dev so a bad pack is noticed.
